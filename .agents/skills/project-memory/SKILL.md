# project-memory

Agent **memory root** is under project root, folder is named `{repo_name}-memory`. It is Obsidian compatible with wiki-style references.

## Concepts and hierarchy

### ongoing memory

**memory root**/ongoing. Treat this as the backlog

What goes here:

- Studies: groups of experiments with a baseline, a KPI goal or a learning goal. Named as study-*. Tag with `#study`, chapter, era
- Increments: groups of code changes, maximum 5 chunks of implementation. Named as increment-*. Tag with `#increment`, chapter, era
- Open Chapters: groups studies and increments. Each begins with a scope definition by user or agent: **Why**, **How**. Ends with **Conclusion**, **Discussion**, **Next steps**. Contains learnings as a section. Named chapter-*
- Bug, risks: any bug or risk that is discovered, but is not immediately fixed or acted upon. Triage by tag of severity: `#bug, #severe`, `#risk, #severe` `*-mild`, `*-meh`.

Keep an up-to-date index of the files: 

### long term memory

**memory root**/longterm. Guidelines, learnings, policies, architectural decisions go here. 1 subfolder per **Era**

- Closed Chapters. Learnings extracted as standalone longterm items when chapter is closed, chapter references them
- Current era + closed Eras: highest level of organization, each era is a folder. Contains chapters or just studies and increments. Can be a simple grouping or some relation based on higher level concepts. Eras are opened and closed by the user, but the agent creates the file system changes. Only 1 era can be open, named `active-era`. Closed era folders are named `era-*`
- Learnings: Has subcategories: tag with fact, decision, policy. Generated by agent or human and must be accepted by both human and agent. May be placed within an era subfolder or in the longerm memory root if the learning is general

## Indices

Keep up-to-date indices of the files: `longterm/LONGTERM.md`, `ongoing/ONGOING.md` that contain the wiki-style ref and a one sentence summary of each memory item.

Long term memory has a hierarchical index. Era folders have their own INDEX.md in them with the appropriate summaries. Closed era INDEX.md is closed with a short summary of the whole era.

## Guidelines

- At session start, read the ongoing memory index
- During a session, record changes, decisions, studies, increments in ongoing memory
- At session end, consolidate the memory
- If a chapter can be closed (conclusion drawn, experiments finished, code changes done), align with the user about conclusions before closing it
- When the active era is closed, rename it and start a new one as per the user's instructions
- human thoughts, conclusions, plans are placed in the folder under memory root named `human_mind`
- never edit the human notes
